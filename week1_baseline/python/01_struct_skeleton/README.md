# 01 · Struct Skeleton (Python)

Python port of `week1_baseline/ruby/01_struct_skeleton`. See
[`docs/plans/python_port/01_struct`](../../../docs/plans/python_port/01_struct)
for the full port plan and the decisions behind the differences from Ruby
called out below.

Let's define data structures for specific data we need to constantly pass
around.
- `boukensha.Tool`
- `boukensha.Message`
- `boukensha.Context`

Ruby represents these as `Struct`s because they're lightweight and readable
for learning; in practice you'd probably use classes. Python's equivalent is
`@dataclass` — a mutable, structurally-equal value object with the same
learning-friendly shape.

`Config`, `Task`, and `Player` are unchanged from
[`00_config`](../00_config/README.md) — this step copies them forward
verbatim (see the plan's "why this step duplicates 00_config's code"
section) and adds the three structures below.

## Differences from the Ruby version

- **`Struct.new` → `@dataclass`.** Both `Tool` and `Message` get a custom
  `__repr__`/`__str__` to match the Ruby `to_s` format as closely as
  Python allows.
- **No symbols.** Ruby's `parameters.keys` on a symbol-keyed hash prints as
  `[:direction]`. Python has no symbols, so `Tool.__repr__` renders
  `params=['direction']` instead — an accepted, documented divergence.
- **`Context` has no `token_budget` field**, even though the Ruby
  `README.md` describes and illustrates one. The actual `context.rb` code
  never implements it, and `example.rb`'s real output never prints a
  budget — the Python port follows the code, not the aspirational README
  (see the plan for details).
- Everything else (`Config`, `Task`/`Player`) is identical to `00_config`.

## Data Structures

### `Tool`

| Field | Description |
|---|---|
| `name` | The name of the tool |
| `description` | Shown to the agent so it knows when to invoke the tool |
| `parameters` | The arguments that need to be passed in |
| `block` | The actual callable that runs when the tool is called |

### `Message`

A single unit of conversation between the user and the agent.

| Field | Description |
|---|---|
| `role` | Who is speaking — `user`, `assistant`, or `tool_result` |
| `content` | The text generated by the agent or provided by the user |
| `tool_use_id` | Links a tool result back to the specific tool call that requested it |

### `Context`

Holds everything Boukensha needs to make an API call. Nothing lives outside
of this.

| Field | Description |
|---|---|
| `task` | The `Task` subclass (e.g. `Player`) driving this context — a class, never instantiated |
| `system` | Tells the agent what its job is |
| `messages` | The full conversation history, replayed on every turn |
| `tools` | The registered tools the agent is allowed to invoke |

## Code Layout

| File | Purpose |
|------|---------|
| `src/boukensha/config.py` | `Config` class (unchanged from `00_config`) |
| `src/boukensha/errors.py` | `ConfigError` (unchanged from `00_config`) |
| `src/boukensha/tasks/base.py` | abstract `Task` (unchanged from `00_config`) |
| `src/boukensha/tasks/player.py` | concrete `Player` (unchanged from `00_config`) |
| `src/boukensha/tool.py` | `Tool` dataclass |
| `src/boukensha/message.py` | `Message` dataclass |
| `src/boukensha/context.py` | `Context` class |
| `src/boukensha/__init__.py` | top-level package exports |
| `prompts/system.md` | default system prompt shipped with the library |
| `examples/example.py` | runnable smoke-test |
| `tests/` | pytest coverage of `Config`, `Task`, `Tool`, `Message`, `Context` |

## Run Example

```bash
./week1_baseline/bin/python/01_struct_skeleton
```

Expected output (values from your `.boukensha/`):

```
=== Boukensha Step 1: Struct Skeleton ===

Config:   #<Boukensha::Config dir=/home/andrew/Sites/Claude-Code-Camp/.boukensha tasks=player>
Context:  #<Context task=player turns=2 tools=1>
Tool:     #<Tool name=move description=Move the player in a direction (north, so params=['direction']>
Messages:
  #<Message role=user content=Explore north and tell me what you find....>
  #<Message role=assistant content=Sure, let me head north and take a look....>
```
